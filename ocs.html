Qué es

Un editor visual para sitios estáticos.

En una frase: una app web que se conecta a un repo de GitHub, renderiza el sitio en un iframe editable, y hace commit de los cambios usando la API de GitHub.

Sin CMS. Sin base de datos. Sin backend propio.

El problema · Parte 1

Editar contenido en un sitio estático es incómodo.

  • Clonar el repo o abrir el editor web de GitHub.
  • Buscar el archivo HTML correcto entre todos.
  • Encontrar el bloque dentro del markup.
  • Editar a mano con riesgo de romper el layout.
  • Commit, push y esperar el build de Pages.
El problema · Parte 2

Y esto genera fricción en ambos lados.

Para el dev

  • Tickets por cambios triviales.
  • Interrupciones constantes.
  • No puede dar acceso al repo sin riesgo.

Para el cliente

  • No puede editar su propio sitio.
  • Depende de alguien para una coma.
  • Alternativa: instalar un CMS completo.
Cómo funciona

GitHub API + iframe editable + commit automático.

No hay backend propio. El navegador habla directo con la API de GitHub usando un Personal Access Token que el usuario ingresa una vez.

Cómo funciona · Detalle

Auth y fetch.

Auth

  • El usuario pega un PAT con scope repo.
  • Se guarda en localStorage.
  • Se valida con GET /repos/:owner/:repo.

Fetch

  • Listado de HTML con GET /git/trees/:branch?recursive=1.
  • Contenido de cada archivo con GET /contents/:path.
  • Base64 decodificado en el navegador.
Cómo funciona · Detalle

Render y edición.

Render

  • El HTML se inyecta en un <iframe>.
  • Un <base> apunta a usuario.github.io/repo/.
  • Así el CSS, fuentes e imágenes cargan reales.

Edit

  • Se manipula el DOM del iframe directamente.
  • Cambios en vivo, sin recargar.
  • Se limpian las inyecciones del editor antes de guardar.
Cómo funciona · Commit

Un único endpoint hace todo el trabajo.

// Un solo PUT crea el commit PUT /repos/{owner}/{repo}/contents/{path} { "message": "Update index.html via OpenCanvas Studio", "content": "<base64 del HTML editado>", "branch": "main", "sha": "<sha actual del archivo>" } → 200 OK · nuevo commit en el repo · GitHub Pages reconstruye solo

Diferencia

Edición visual sobre Git, sin CMS.

CMS Git-based (Tina, Decap, Pages CMS)
  • ✕ Edición por formularios, no visual
  • ✕ Schema por cada campo
  • ✕ Requieren OAuth con backend
  • ✕ No mueven ni redimensionan
  • ✓ Multi-usuario y flujo editorial
OpenCanvas Studio
  • ✓ Edición directa sobre el HTML renderizado
  • ✓ Sin schemas ni configuración
  • ✓ Sin backend: PAT directo a la API
  • ✓ Funciona con cualquier HTML existente
  • ✕ Un usuario por sesión

No compite con un CMS. Es una capa de edición visual para sitios que no necesitan uno.
