◐ OpenCanvas Studio
Editor visual · GitHub Pages

Edita sitios estáticos sin tocar el código.
Los cambios se guardan como commits.

OpenCanvas Studio es una app web que se conecta a un repo de GitHub, renderiza el sitio en un iframe editable, y hace commit de los cambios usando la API de GitHub.

En una frase: un editor visual para sitios estáticos alojados en GitHub Pages que genera commits automáticos — sin CMS, sin base de datos, sin backend propio.

El problema

Editar contenido en un sitio estático es incómodo.

Actualmente, cambiar un texto o una imagen en un sitio en GitHub Pages implica:

Flujo actual del cliente

  • Clonar el repo o abrir el editor en GitHub.
  • Buscar el archivo HTML correcto.
  • Encontrar el bloque dentro del markup.
  • Editar a mano con riesgo de romper el layout.
  • Hacer commit y esperar el build de Pages.

Consecuencia

  • El cliente no puede editar su propio sitio.
  • El desarrollador recibe tickets por cambios triviales.
  • Alternativas: instalar un CMS (más infra) o dar acceso al repo (riesgo).
  • Mantener WordPress / Strapi / similar para sitios que son solo HTML.
Cómo funciona

GitHub API + iframe editable + commit automático.

No hay backend propio. El navegador habla directo con la API de GitHub usando un Personal Access Token que el usuario ingresa una vez.

PASO 01

Auth

El usuario pega un PAT. Se guarda en localStorage. Se valida contra GET /repos/:owner/:repo.

PASO 02

Fetch

Se listan los HTML del repo con GET /git/trees/:branch?recursive=1 y se traen los contenidos con GET /contents/:path.

PASO 03

Render

El HTML se inyecta en un <iframe> con un <base> que apunta a usuario.github.io/repo/ para resolver CSS e imágenes.

PASO 04

Edit

El usuario mueve, redimensiona y edita elementos. Los cambios se aplican al DOM del iframe en tiempo real.

PASO 05

Commit

Al guardar, se serializa el DOM, se limpian inyecciones, y se hace PUT /contents/:path con base64 + sha.

// El commit se hace con la API REST, sin backend PUT /repos/{owner}/{repo}/contents/{path} { "message": "Update index.html via OpenCanvas Studio", "content": "<base64 del HTML editado>", "branch": "main", "sha": "<sha actual del archivo>" } → 200 OK · nuevo commit en el repo · GitHub Pages reconstruye solo

Diferencia

Edición visual sobre Git, sin CMS.

CMS Git-based (Tina, Decap, Pages CMS)
  • ✕ Edición basada en formularios sobre front-matter, no visual
  • ✕ Requieren configuración de schema por cada campo
  • ✕ OAuth con backend o servicio externo para GitHub Pages
  • ✕ No permiten mover ni redimensionar elementos
  • ✓ Multi-usuario y flujo editorial
  • ✓ Formularios estructurados
OpenCanvas Studio
  • ✓ Edición directa sobre el HTML renderizado, sin schemas
  • ✓ Drag, resize y edición in-place como en Figma
  • ✓ Sin backend: PAT directo a la API de GitHub
  • ✓ Funciona con cualquier HTML existente, sin migración
  • ✕ Un solo usuario por sesión
  • ✕ No hay flujo editorial ni revisión

No compite con un CMS. Es una capa de edición visual para sitios que no necesitan uno.

Casos de uso

Dónde tiene sentido.

Agencias y freelancers

  • Entregar el sitio al cliente con editor incluido.
  • Evitar tickets por cambios de texto o imágenes.
  • No instalar WordPress solo para que el cliente edite.

Landings y sitios one-page

  • Sin CMS completo para una sola página.
  • Cambios frecuentes: precios, textos, banners.
  • El cliente edita sin tocar el repo.

Portafolios y sitios personales

  • Actualizar proyectos sin abrir VS Code.
  • Editar desde el navegador en cualquier equipo.
  • Sin instalar nada, sin build, sin CLI.
